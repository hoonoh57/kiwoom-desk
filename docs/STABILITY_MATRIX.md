# Kiwoom Desk Stability Matrix

## 1. 목적

이 문서는 Kiwoom Desk의 각 표준 기능이 어느 검증 단계에 있는지 기록한다.

상태는 구현량이 아니라 **확보된 검증 증거**를 기준으로 판정한다.
기능이 화면에 보이더라도 오류·빈 응답·재접속·연속조회·폼 연동이 검증되지 않았다면 Stable로 올리지 않는다.

## 2. 상태 정의

| 상태 | 의미 |
|---|---|
| Planned | 구현 전이거나 구현 범위와 계약이 확정되지 않음 |
| Implemented | 코드와 화면이 존재하지만 실제 동작 검증이 부족함 |
| Tested | 실제 호출 또는 재현 가능한 절차로 주요 정상 동작을 확인함 |
| Stable | 정상·오류·빈 응답·수명주기·연동·빌드·회귀 검증을 완료함 |

상태 전이는 다음 방향으로만 진행한다.

`Planned -> Implemented -> Tested -> Stable`

버그나 계약 불일치가 발견되면 상태를 낮추고 원인과 복구 조건을 기록한다.

## 3. Stable 공통 게이트

모든 기능은 다음 증거를 확보해야 Stable로 판정할 수 있다.

1. API ID 또는 WebSocket 거래 종류 확인
2. 요청 필드와 필수값 확인
3. 응답 필드와 정규화 규칙 확인
4. 정상 응답 확인
5. 실패 응답 확인
6. 빈 응답 확인
7. 연속조회 또는 실시간 등록 수명주기 확인
8. timeout과 재접속 확인
9. 중복 실행과 빠른 사용자 전환 확인
10. TypeScript 검사 통과
11. production build 통과
12. `git diff --check` 통과
13. 관련 표준 폼과 종목 연동 확인
14. 재현 절차 또는 fixture 확보
15. 완료 커밋과 검증 일자 기록
